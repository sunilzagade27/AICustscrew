This spec defines the MVP frontend for the Critical Research Workflow. Services are **stubs** until `@integration.eng` wires live APIs.

---

## 1. Inputs

| Input | Type | Required | Validation | UI |
| --- | --- | --- | --- | --- |
| `symptom` | string | Yes | Non-empty after trim; max 8192 chars | Textarea on Inputs form |
| `runId` | string (UUID) | System | Generated by `startRun` | Not user-editable |

**Behavior**

- Empty / whitespace-only submit → inline validation; no `startRun` call (AC-002).
- Valid submit → transition FSM `idle → running` and call `startRun({ symptom })` (AC-001).
- Prefer inline panels over modals (`aamad.config.yml` `prefer_modals: false`).

---

## 2. Run

| Concern | Spec |
| --- | --- |
| FSM states | `idle` → `running` → `done` |
| Start | `startRun(payload)` returns `{ runId, status: "running" }` |
| Poll | While `running`, poll `getRunStatus(runId)` until `status === "done"` (or error) |
| UX | Show Run panel: status label, runId, “Investigation in progress…” |
| Errors | Stub may return failure; show operational error text; allow reset to `idle` |

**FSM rules**

| From | Event | To |
| --- | --- | --- |
| `idle` | `SUBMIT_VALID` | `running` |
| `running` | `STATUS_DONE` | `done` |
| `running` | `STATUS_ERROR` / `RESET` | `idle` (after user acknowledges) |
| `done` | `RESET` / `NEW_RUN` | `idle` |

Illegal transitions are no-ops and logged in the console in development.

---

## 3. Results

Shown when FSM is `done`.

| Field | Description |
| --- | --- |
| `runId` | Investigation / run identifier |
| `summary` | Short operational summary (stub text) |
| `findings` | List of specialist-style finding lines (stub) |
| `sources` | Source IDs for grounding (stub IDs, e.g. `stub-k8s-1`) |
| `completedAt` | ISO timestamp |

**UX**

- Results panel replaces/follows the Run panel on the same route.
- Stub banner: “Demo / stub data — not live cluster telemetry.”
- Primary action: “New research run” → `RESET` → Inputs.

---

## 4. History

| Scope | MVP behavior |
| --- | --- |
| Persistence | **Session-local only** (in-memory React state). No durable store (SAD: FR-105/FR-106 deferred). |
| Entry | On each successful `done`, append `{ runId, symptomPreview, completedAt, status }` |
| UI | History list on the same `/` route (collapsible / side section) |
| Actions | Select entry to re-show Results snapshot for that run (stub); does not re-kick crew |
| Future Work | Similar-incident lookup, AgentCore memory namespaces — visible label only |

---

## 5. Technical shape (implementation contract)

- **Stack**: React + TypeScript (Vite). Single route `/`.
- **Theme**: minimal; system preference (`ui.theme: system`).
- **Services** (stub): `src/services/runService.ts` — `startRun`, `getRunStatus`.
- **FSM**: `src/fsm/runFsm.ts` — pure transition helper.
- **No live CrewAI / FastAPI calls** in this epic.

## Assumptions

1. Operator requested a **form + results** Critical Research Workflow on a single route; SAD §3 describes a **chat** composer. This MVP implements the form/results layout; chat-style composer remains an Open Question for alignment with `@frontend.eng` chat default.
2. Vite + React SPA is used instead of Next.js App Router for the single-route stub shell; production may migrate to Next.js per SAD AD-05 without changing §1–§4 contracts.
3. Stub `getRunStatus` completes after a short delay with canned findings (no LLM).
4. History is session-local only and does not claim FR-105/FR-106 completeness.

## Open Questions
